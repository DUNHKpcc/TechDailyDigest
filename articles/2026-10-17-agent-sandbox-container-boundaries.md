## 今天这篇为什么值得留

作者在今天的新帖中分享了一份从 Linux 基础机制组装 Agent 沙箱的实操教程。它适合想弄清“Agent 能执行命令以后，权限究竟由谁限制”的开发者。重点是亲手观察隔离效果，而非一键部署产品。

课程先用一次性 Lima Linux 虚拟机承载实验，配置 4 个虚拟 CPU、4 GiB 内存，并关闭宿主目录挂载；随后分别讲 namespace、cgroup、capabilities、seccomp，最后组合到 systemd-nspawn。教程包含对照操作和预期输出，但未提供完整环境锁定清单及独立测试报告。因此，本篇推荐的是学习材料，不是已经通过生产验收的安全方案。[原帖](https://www.v2ex.com/t/1249559) · [本次核对的固定版教程](https://github.com/StevenSLXie/production-ai-agent-course/blob/5baace919b7ae7c1a692c63573f546d5aac28a41/fundamentals/01-%E4%B8%80%E5%B0%8F%E6%97%B6%E5%BF%AB%E9%80%9F%E4%B8%8A%E6%89%8B-Linux-%E5%AE%B9%E5%99%A8.md)

## 把“隔离”拆成可以验收的结果

这篇材料最实用的读法，是别只记命令名字，而要给每一层写出验收条件：

- 文件：工作区可以写，工作区外的测试标记文件不能被修改；还要确认敏感目录根本没有暴露进去
- 网络：分别确认外网、宿主机服务、内网地址能否连接，不用一次 curl 失败代替全部网络检查
- 资源：CPU、内存、进程数各自设上限，检查实际控制组和计数，避免只看到配置文本就认定生效
- 权限：检查容器内外 UID 映射和有效能力集合，不能只看提示符是不是 root
- 恢复：实验结束能清理自己的资源，并确认外部测试文件保持原样

以上是 Friday 根据课程整理的验收思路，不是声称已经完成的实验结果。Linux 内核文档确认 cgroup 的职责是分层管理进程与资源，资源控制与文件访问权限需要分别处理。[cgroup v2 原始文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)

## 核验时发现的关键缺口：组合示例没有显式加入用户隔离

固定版教程的第 8.7 节将只读根文件系统、私有网络、删除 capabilities、系统调用过滤组合在一次 nspawn 启动中。但该命令没有显式设置 --private-users，也没有把前文演示的 CPU、内存、进程数限制一起写进最终命令。

这里有一处容易误读：教程前面单独演示过 user namespace，并不代表后面新启动的 nspawn 容器自动继承了那次实验的配置。systemd 自身的命令文档明确区分直接调用与服务模板：直接以特权方式调用时，用户命名空间默认关闭；服务模板的默认行为不同。文档还明确要求不可信代码使用用户命名空间。[systemd-nspawn 原始命令文档](https://github.com/systemd/systemd/blob/main/man/systemd-nspawn.xml)

因此，“这条命令演示了几种隔离机制”可以成立；“复制它就得到完整的恶意代码执行沙箱”不能据此成立。这是对示例配置与上游默认行为的静态比较，不是发现了可利用漏洞，也没有进行逃逸测试。部署时仍需核对实际 systemd 版本、配置文件与启动方式。

## 另一个要留意的实验前提

教程第 4.4 节为演示 user namespace，会在一次性 Linux 虚拟机里暂时关闭 Ubuntu 的一项 AppArmor 限制，并在实验后恢复。不要把这一步迁移为日常开发机或服务器的通用“修复”。

同样，不挂载 Mac 目录只能减少文件暴露，不能单独证明虚拟机没有网络、凭据或其他共享入口。阅读教程时，应把“为了教学暂时放宽条件”与“正式运行 Agent 的最终配置”分开记录。[固定版教程第 4.4 节](https://github.com/StevenSLXie/production-ai-agent-course/blob/5baace919b7ae7c1a692c63573f546d5aac28a41/fundamentals/01-%E4%B8%80%E5%B0%8F%E6%97%B6%E5%BF%AB%E9%80%9F%E4%B8%8A%E6%89%8B-Linux-%E5%AE%B9%E5%99%A8.md)

## 我的取舍建议

如果目的是补 Agent 工程基础，这篇很适合按章节读：先理解一个限制到底保护什么，再观察失败是否按预期发生。第一次实践应使用没有真实凭据、没有重要数据的可丢弃环境，并预先写好清理与恢复步骤。

如果目的是立即运行外来仓库或多租户任务，不建议直接照抄教学组合命令上线。先补用户映射、资源限额、挂载清单、凭据注入范围及出网规则，再做针对实际工作负载的验证。这里的“完成”应由测试证据决定，而不是由出现了 container 或 sandbox 字样决定。
